## Grading

Assignment 3 is worth **14 points**.

- your AI's ability to play the game

- your presentation and explanation of your AI after the A3 deadline (A3 assignment interview)

The coding style will not be evaluated for this assignment.

<details>
<summary><h3>Details about the Grading</h3></summary>

The points for A3 are calculated as follows:

```
A3 points = AI points - deductions
```

Your AI will play against three different AIs created by the course team (Easy/Medium/Hard Tutor AI). Against each tutor AI, your AI will be evaluated on multiple different game configurations. 

For each game configuration, two games will be played, once with your AI as Player 1 and once as Player 2, to ensure fairness. From the results of these two corresponding games, an indicator is calculated.

| result         | indicator |
|----------------|-----------|
| 2 wins         | 1         |
| 1 win, 1 draw  | 0.8       |
| 1 win, 1 loss  | 0.6       |
| 2 draws        | 0.4       |
| 1 draw, 1 loss | 0.2       |
| 2 losses       | 0         |

All indicators received from playing against the same Tutor AI are then averaged, and multiplied by a factor depending on the Tutor AI. The resulting points from playing against all three Tutor AIs are summed up.

```
AI points = average-easy-indicator * 6 + average-medium-indicator * 4 + average-hard-indicator * 4
```

</details>

## Tasks in A3
In this assignment, you will extend **your existing implementation of A2** by adding an artificial intelligence (AI). The AI should calculate the best actions for the player currently taking their turn in the `Setup Phase`.

In this assignment, you will add three new commands to your implementation. The new commands
should be executable whenever your program waits for user input in the `Setup Phase`. The handling of 
**invalid number of parameters** errors should be extended to also include the new commands.

<details>
<summary><h3>Command: whoami</h3></summary>

The command `whoami` prints the name of your team in the following format:

```
Team: <NAME>\n
```

Here, `<NAME>` is a placeholder and should be replaced by your team's name. This name may be chosen arbitrarily (max. 20
ASCII or UTF-8 encoded characters). Creative team names are very welcome. However, please try to refrain from using names that may be considered offensive. The team name printed by `whoami` will appear later in a high score list, which is managed by the course team. Your program should always output the same team name with the `whoami` command.

> **Attention:** This command is mandatory! You will not get any points if this feature is not implemented.

<details>
<summary>Example</summary>

```
P1> whoami\n
Team: Easy Tutor AI\n
```

<details>
<summary><h3>Command: play</h3></summary>

When the command `play` is entered, the AI should take over and choose a single command to issue during the `Setup Phase` for the current player. This command must be printed as shown below and then executed as if it were a regular user input.

The main goal of the AI is to win the game (see [Grading](#grading) for a detailed explanation on what results are preferable).

> **Attention**: The execution of a single `play` command must not take longer than 1 second, otherwise the game will be aborted.

#### Choice of Command

The AI is not allowed to choose `quit` or commands that only print information (see the [Specifications](#specifications)). This means that the AI is only allowed to choose one of the following:
- Command: redraw
- Command: done
- Command: battle
- Command: creature
- Command: spell

If the AI determines that there are no useful actions to take, it should end the player's turn by issuing the `done` command. The AI is not allowed to choose a command that results in an error message.

#### Output

The `play` command's output has the following format:

```
AI: <CHOSEN_COMMAND> <PARAMETERS>\n
```

where the placeholders `<CHOSEN_COMMAND>` and `<PARAMETERS>` specify the chosen command and its parameters, respectively. 

All commands and parameters should be printed in lower case letters. There should always be a single space between the 
command and the first parameter, as well as between parameters. There should not be a space after the last parameter.

Any output resulting from the executed command (e.g. [INFO] messages) should be printed **after** this output line. 

<details>
<summary>Examples</summary>

```
P1> play\n
AI: battle f3 b3\n
```

```
P1> play\n
AI: redraw\n
```

```
P2> play\n
AI: creature agrat f2\n
[INFO] Squeak squeak.\n
```

```
P2> play\n
AI: spell shock of1\n
[INFO] Get shocked!!!\n
```

</details>

#### Usable Information

The AI knows all rules of the game, including details e.g. in which order slots are evaluated. The AI is allowed to know the value of the `<MAX_ROUNDS>` parameter.

Additionally, the AI may access any information that a human player could get from the automatic game output or by entering commands on their turn. This includes:
- the game board (e.g. placement of creatures)
- the game status (e.g. role, health, mana, remaining deck size, and graveyard size for both players)
- their own hand cards
- both graveyards (the opponent's graveyard is known to a human player via the game play up to this point)
- the current round counter
- the base values of any card that may exist in the game (a human player can access these via the `info` command)
- the current values of creatures in the game (known to a human player via the game play up to this point)

It does not include:
- their own draw pile
- the opponent's hand cards and draw pile

If the AI accesses information that it is not allowed to use, there will be a deduction of -100 % (see the [Specifications](#specifications)).

</details>
